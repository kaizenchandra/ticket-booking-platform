# Failure analysis and evidence

The following matrix distinguishes executed tests from code-path analysis and unimplemented extensions. “Executed”
refers to JUnit tests, not proof at arbitrary scale.

| # / scenario                              | Mechanism, risk and user impact                                  | Detection                               | Prevention / concurrency                                       | Recovery                                             | Automated evidence / approach                                              | Residual risk                               |
|-------------------------------------------|------------------------------------------------------------------|-----------------------------------------|----------------------------------------------------------------|------------------------------------------------------|----------------------------------------------------------------------------|---------------------------------------------|
| 1 / Last seat, two customers              | Concurrent stale reads could oversell; one customer sees 409     | Hold conflict counter, ownership query  | Inventory row lock and ownership check                         | Refresh selection; retry same key only on ambiguity  | Executed: parameterized 2-request contention                               | Single primary required                     |
| 2 / 10,000 attempts on one seat           | Hot lock queue exhausts capacity; long waits                     | Pool waiters, lock waits, 503           | Admission, bounded pool, gateway shedding                      | Reduce admissions; backoff with jitter               | Executed: 10,000 offered calls, one owner; bounded-pool rejections counted | Sustained HTTP throughput unmeasured        |
| 3 / Partial multi-seat failure            | Some rows lock before unavailable row; orphan holds possible     | Hold/item counts, 409                   | One transaction; validate before assigning                     | Rollback returns previous ownership                  | Executed: multi-seat rollback                                              | Operator SQL may bypass rules               |
| 4 / Hold commit, response lost            | Caller cannot tell whether inventory reserved                    | Idempotency lookup                      | Persist replay record in same commit                           | Retry original key and fingerprint                   | Executed: repeated hold call                                               | Client must retain key                      |
| 5 / Customer retries hold                 | Duplicate intent could consume more seats                        | Replay key conflicts                    | User/operation/key uniqueness and fingerprint                  | Return original hold including current state         | Executed: retry and changed-fingerprint conflict                           | Keys have no retention job                  |
| 6 / Hold expires during payment           | Payment ambiguity outlives inventory; checkout fails             | Expiry lag, pending payment state       | No unlimited pending extension; deadline conditional           | Release inventory, refund any late capture           | Executed: expired settlement race                                          | Real refund adapter absent                  |
| 7 / Payment succeeds after expiration     | Captured funds without seats                                     | LatePaymentRefunded event               | Never confirm expired or reassigned ownership                  | Simulator refund ledger                              | Executed: late payment after reassignment                                  | External refund success not proven          |
| 8 / Expiry races confirmation             | Competing transitions may clear sold seat                        | State/invariant queries                 | Same hold lock; final DB time condition                        | One transaction wins, other observes new state       | Executed: active/expired concurrent paths                                  | Deadline timing beyond local tests unproven |
| 9 / Old expiry releases new owner         | Stale worker could clear reassigned seat                         | Inventory owner vs hold audit           | Owner-qualified clear and UUID ownership tokens                | Ignore inventory with newer hold ID                  | Executed: reclaim then old expiry                                          | Manual broad SQL dangerous                  |
| 10 / Provider charges, response times out | Retry may charge twice; user waits                               | Pending payment age                     | Stable provider intent ID and reconciliation                   | Simulator TIMEOUT resolves at 30s                    | Simulator path implemented; external fault untested                        | External provider idempotency required      |
| 11 / Webhook delivered twice              | Duplicate confirmation/refund events                             | Webhook unique ID conflict              | Deduplicate ID in settlement transaction                       | Return successful no-op                              | Executed: signed duplicate webhook                                         | Dedupe retention must exceed replay window  |
| 12 / Webhook before sync response         | Two paths concurrently settle intent                             | Payment state transition audit          | Persist payment before effect; common settle method            | Return persisted terminal result                     | State convergence covered; network ordering not injected                   | No external network provider                |
| 13 / Out-of-order payment events          | Failure after capture could free sold seats                      | Payment state audit                     | No regression from CAPTURED; late capture after FAILED refunds | Reconcile provider truth                             | Executed: CAPTURED then FAILED                                             | Real provider lifecycle needs mapping       |
| 14 / Booking commit, response lost        | Repeated bookings may share hold                                 | Unique hold_id and replay table         | Lock hold; UNIQUE booking hold                                 | Return original booking                              | Executed: distinct keys same hold                                          | Client must preserve intent                 |
| 15 / Ticket issuance fails                | Paid buyer temporarily lacks ticket                              | Outbox backlog/oldest event             | Transactional outbox and unique ticket allocation              | Replay event after worker restart                    | Executed: deferred issue/repeated outbox                                   | Poison-event DLQ absent                     |
| 16 / Kafka unavailable                    | If enabled, delivery stalls, inventory remains safe              | Broker lag/publish errors               | Current baseline has no Kafka dependency                       | Future relay retries durable outbox                  | Design only; Kafka not implemented                                         | No broker failover proof                    |

| 18 / PostgreSQL primary fails             | Writes unavailable; ambiguous commits                            | DB health, pool failures                | One fenced primary; transactions roll back on loss             | Failover with WAL verification, retry original keys  | Not injected                                                               | RPO/RTO depend on deployment                |
